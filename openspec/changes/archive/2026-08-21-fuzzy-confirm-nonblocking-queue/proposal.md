# 模糊匹配确认改为非阻塞队列

## 背景

批量补全 MusicBrainz 数据时，专辑精确匹配失败会触发模糊匹配确认弹窗。
当前实现为串行阻塞式：批量循环逐张处理专辑，遇到需要确认的专辑时暂停整个流程，
等待用户在弹窗中回复后才继续处理下一张。

一次性同步大量专辑时，用户必须全程守在弹窗前逐张确认，
补全流程无法在用户处理弹窗期间继续推进，
整体耗时 = 扫描时间 + 用户确认时间，用户体验差。

## 目标

- 弹窗不再阻塞批量补全扫描流程：扫描循环遇到模糊匹配专辑时仅入队，立即继续处理后续专辑
- 待确认弹窗按队列依次弹出（同一时刻最多一个），用户可随时处理
- 用户确认/跳过后的写库逻辑保持不变（确认后 lookup 详情、写库、学习别名；跳过标记 enriched_at）
- 保留弹窗内手动粘贴 MB 链接的能力（候选为空时同样入队）
- 弹窗内展示队列剩余数量，让用户感知待处理规模

## 非目标

- 不改变模糊匹配的候选生成逻辑（F1/F2/F3 策略不变）
- 不改变精确匹配与风格标签保护逻辑
- 不做弹窗的批量列表化展示（维持逐条弹窗交互）
- 不改变 MusicBrainz API 请求频率控制
